## ADR-001 — Reference site and what not to copy

**Date:** 2026-10-29

**Context.** The structural reference is ana-pfeilsticker-developer.vercel.app (Next.js + Tailwind + shadcn + Framer Motion + Formspree). ## ADR-002 — Content separated from code, validated with Zod

**Date:** 2026-10-29

**Context.** The site will be edited often. Editing JSX to change a sentence is slow and error-prone, and the owner's credibility depends on not publishing unverifiable claims.

**Decision.** All facts live in typed files under `src/content/`. Zod schemas define the rules (verified certification ⇒ URL; every project lists limitations; both languages required; no placeholders in visible items). Validation runs at import time, so the build fails on invalid content. A Vitest "claims guard" blocks banned terms.

**Alternatives considered.** Notion as CMS (API rate limits, image URLs expire after 1 h, external dependency at build time); MDX only (no structured validation).

**Consequences.** Editing = change a `.ts` file, commit, push. Honesty rules are enforced by the build, not by memory.

## ADR-003 — English by default, Portuguese available, no auto-detection

**Context.** Targets include multinationals and Brazilian programs (iFood GenAI). The owner asked to launch in English with a Portuguese option.

## ADR-004 — Native Next.js i18n instead of next-intl

**Date:** 2026-10-29

**Context.** Next.js 16 documents a native pattern: a `[lang]` root segment, `next/root-params` to read it anywhere on the server, dictionaries loaded per locale, and `proxy.ts` for redirects. next-intl was installed initially.

**Decision.** Use the native pattern and remove next-intl.

**Consequences.** One fewer dependency and no compatibility risk with Cache Components. UI strings are few, so next-intl's features (ICU plurals, formatters) are not needed; dates use `Intl.DateTimeFormat`.

## ADR-009 — Theme stored in localStorage, applied by an inline script

**Date:** 2026-10-29

**Context.** Dark is the default; visitors can switch to light. Reading a cookie on the server would make every page dynamic (Cache Components) and lose static prerendering. Applying the theme after hydration causes a visible flash.

**Decision.** Follow the Next.js 16 "preventing flash before hydration" guide: an inline script in `<head>` reads `localStorage.theme` (only `light`/`dark` accepted) and sets `data-theme` before the first paint. `<html suppressHydrationWarning>`. The toggle syncs via `useSyncExternalStore`.

**Consequences.** Pages stay static. One inline script must be allowed by the CSP in Part 7 (by hash, not `unsafe-inline`).

## ADR-017 — Certifications verifiable by certificate number (PeopleCert)

**Date:** 2026-11-05

**Context.** ADR-002 shows a certification only with a verification URL. PeopleCert (ITIL 4 Foundation) gives no free per-certificate link: digital badges need a paid PeopleCert Plus membership. It does run a free public Certificate Verification Service where anyone types the certificate number.

**Decision.** A `verified` certification may add `lookupId`: the certificate number exactly as printed (format-checked). `credentialUrl` then points to the issuer's verification portal, and the card shows "Verify at {issuer} · Certificate no. {lookupId}". The candidate/customer number is never stored or shown.

**Alternatives considered.** Hide ITIL until a badge exists (loses the strongest service-management credential); pay for PeopleCert Plus; host the certificate image (shows the full legal name and staff signatures, and an image proves nothing).

**Consequences.** The rule "every shown certification can be checked by a stranger" still holds. Used only where the issuer has no per-certificate page; SkillFront and Microsoft Learn have one and use plain links.

## ADR-020 — Writing section reads the blog's RSS feed (newest 3, title + date)

**Date:** 2026-11-05

**Context.** The plan was one hand-picked post in `writing.ts`. Gustavo wants the section to follow the blog without editing the site. ggblog99.wordpress.com publishes every post in EN/PT pairs, marked by the categories "English" and "Português", and exposes a public RSS feed.

**Decision.** The server fetches `/feed/` inside a `"use cache"` function with `cacheLife("hours")` (background refresh about hourly; `"minutes"` after a failure) and shows the **3 newest posts in the page's language**, **title and date only**, plus a link to the blog. Titles pass through the claims guard (`src/content/claims.ts`, now shared with the tests); a post whose title hits it is skipped. `blog.hidden` lists post URLs to suppress by hand. A small dependency-free parser reads the feed; any error yields an empty list and the section shows only "Read the blog".

**Alternatives considered.** Link to the blog only (no evidence of writing on the portfolio); hand-picked posts (goes stale); WordPress REST API (no advantage over RSS here); showing excerpts (more unreviewed text on the site).

**Consequences.** New posts appear within about an hour with no deploy. Blog text reaches the site without a per-post review, limited to titles and filtered by the guard. The fetch is server-side, so Part 7's CSP needs no `connect-src` for WordPress. `blog.allowed` lists posts Gustavo reviewed that may show even if the title trips the guard: the ServiceNow bootcamp posts name "Aoop and NTT DATA" as the bootcamp's organizers, not as an employer (SOURCES.md forbids NTT DATA only as employer). The guard keeps blocking the term everywhere else.

## ADR-021 — Contact form via Formspree (AJAX with native fallback)

**Date:** 2026-11-05

**Context.** The site is static and has no backend. The briefing asks for a contact form; no phone or WhatsApp. Gustavo created the Formspree form "Portfolio" (free plan), delivering to gustavohfr2003@gmail.com.

**Decision.** A client component posts to `https://formspree.io/f/mvkkyvdv` with `fetch` and `Accept: application/json`, showing the result inline (`role="status"`). The `<form>` also has `action`/`method`, so it still works without JavaScript. Spam: Formspree's honeypot field `_gotcha` + Formshield (on). CAPTCHA stays off because Formspree's CAPTCHA doesn't work with AJAX submissions. A one-line notice says what is collected and why (LGPD). **Consequences.** Part 7's CSP needs `connect-src https://formspree.io` and `form-action https://formspree.io`. Domain restriction is a paid Formspree feature; not used. Tests mock Formspree, so no test email reaches the inbox.

## ADR-022 — CSP keeps the site static: `'unsafe-inline'` for scripts, everything else strict

**Date:** 2026-11-05

**Context.** The plan (ARCHITECTURE, ADR-009) was a CSP without `'unsafe-inline'`, allowing only the theme script by hash. Measured on the build: every page has **36 inline scripts** — the theme script plus Next.js's RSC payload (`self.__next_f.push(...)`), whose content changes with every build and every blog refresh, so hashes can't be listed. A strict hash-only CSP simulated in the browser produced 36 violations and broke the theme toggle and the contact form. Next.js 16's documented alternative is a per-request nonce, which requires dynamic rendering of every page and is incompatible with the Partial Prerendering this site uses.

**Decision.** Stay static. `script-src 'self' 'unsafe-inline'` and `style-src 'self' 'unsafe-inline'`; every other directive strict: `default-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`, `base-uri 'self'`, `connect-src`/`form-action` limited to self + Formspree, `upgrade-insecure-requests`. Plus HSTS (2 years, preload), `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`, COOP `same-origin`; `X-Powered-By` removed. Headers live in `security-headers.ts` and are tested.

**Why the risk is acceptable (threat model).** `'unsafe-inline'` matters when an attacker can inject markup into the page. Here there is no injection path: no visitor content is ever rendered (contact messages go to Formspree and email, never back to the page), there are no third-party scripts, and the only external text — blog titles — is rendered by React, which escapes it.

**Consequences.** Mozilla Observatory deducts 20 points for `'unsafe-inline'`, so this site will likely not reach A+ (Autoria em Forma, a different architecture, does). The grade is measured and recorded on the live site in Part 8, as for every number. Revisit if the site ever renders user content, adds third-party scripts, or Next.js ships hash support for its inline payload.

## ADR-026 — Post-launch technical fixes: localized 404, Person JSON-LD, own icons

**Date:** 2026-11-08

**Context.** The post-launch review (ROADMAP "After launch") found: unmatched paths fell through to Next.js's default 404 (English, unstyled, even under `/pt`); no structured data; the favicon was still the `create-next-app` default (the same kind of leftover ADR-001 criticized in the reference site); the header overflowed by 31 px at 320 px, which fails WCAG 1.4.10 at 400% zoom; and the profile-card name was an `h2` before the page `h1`. Lighthouse, Observatory and axe were otherwise clean.

**Decision.**
- `[lang]/not-found.tsx` renders inside `SiteShell` in the URL's language. A catch-all `[lang]/[...missing]/page.tsx` calls `notFound()` so unmatched paths reach it (in this app `[lang]` is the root segment, so there is no app-level not-found to fall back on). `generateStaticParams` returns one unused param set because Cache Components requires at least one.
- `Person` JSON-LD on the home page with name, job title, headline, location, languages and `sameAs` (LinkedIn, GitHub, blog), taken from `src/content` only. It is data, not a script the browser runs, so the CSP is unchanged; `<` is escaped.
- Icons generated once from Geist Bold: "GR" in the silver gradient on the near-black background (colors from the tokens; static files, like the OG image exception).
- Below 380 px the header controls shrink to 30–32 px.

**Alternatives considered.** `global-not-found.js` (experimental; bypasses the layout, so the shell and fonts would be duplicated); keeping the default favicon; a hamburger menu at 320 px (hides the navigation for one breakpoint).

**Consequences.** The 404 title is the site title (Next.js doesn't accept page metadata from `not-found.js`, and a `<title>` rendered there is dropped); the page is `noindex`. On a streamed 404 the `<head>` theme script doesn't run, so the toggle applies the stored theme on mount: one frame of dark on 404 pages only. The first request to an unknown slug may still return HTTP 200 (unchanged caveat).
